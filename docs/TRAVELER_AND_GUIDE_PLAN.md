# 여행자와 로컬 가이드 운영 제안

이 문서는 다음 테스트 운영을 위한 제안입니다. 운영 인력, 모집, 영업시간,
환불 기한, 실제 현금 지급을 확정하거나 외부에 공지한 내용이 아닙니다.

초기 모델은 가상 포인트와 실제 채택 기록으로 결정되었습니다. [도시 후보와 범위](CITY_COVERAGE.md)는 구현 제안이며 도시별 운영 개시는 별도입니다.

## 이번 MVP에서 확인할 이용 흐름

- 해외에서 인터넷이 느린 여행자: 지도·사진을 기다리지 않고 도시를 직접
  선택하고 짧은 글 질문을 작성합니다. 질문 예시를 골라도 입력한 내용은
  허락 없이 덮어쓰지 않습니다.
- 출발 전 한국에서 여행을 준비하는 사람: 여행지 밖 GPS 때문에 막히지
  않고 목적지 도시를 지정합니다. 도시 중심 좌표는 현재 위치인 것처럼
  표현하지 않습니다.
- 이동 중 연결이 끊긴 사람: 작성한 텍스트를 복원하고, 결과가 불확실한
  제출은 같은 요청으로 재시도합니다. 사진의 재첨부가 필요한 경우는
  텍스트 저장과 구분해 안내합니다.
- 해당 지역 답변자: 신청·승인된 활동 지역의 질문을 확인하고 수락합니다.
  답변은 근거 링크와 확인 방법을 포함합니다. 여행자가 채택해야 보상이
  지급되며, 기록에 근거한 채택 수·획득/대기 가상 포인트를 확인합니다.

‘승인’은 앱에서 답변에 참여할 권한을 뜻합니다. 지역 전문 자격, 신원,
답변 정확성을 인증했다는 의미가 아닙니다. 채택 수는 실제 채택된 답변의
수이며 별점·만족도·응답 속도로 바꾸어 표현하지 않습니다.

## 질문이 답변자보다 많은 초기 운영

### 1. 좁게 시작하는 방안

- 유럽·미국 주요 도시가 목표 범위입니다. 전체 후보 도시의 상시 대응을 약속하기보다, 실제 가이드가 확보된 몇 개 도시의 생활권과
  교통·언어처럼 짧고 출처를 제시하기 쉬운 질문 유형을 우선 검증합니다.
- 실제 참여할 가이드가 확정된 시간대를 정한 뒤에만 테스트 운영 시간을
  공지합니다. 시간대와 인원이 정해지기 전에는 ‘온라인’, ‘즉시 답변’,
  ‘몇 분 이내’ 문구를 사용하지 않습니다.
- 긴급 구조·의료·법적 판단을 대신하는 서비스로 안내하지 않습니다.
  현지 응급 연락이나 즉시 행동이 필요한 상황을 유료 질문 대기로 붙잡지
  않도록 서비스 범위를 명확히 해야 합니다.

### 2. 부족한 공급을 숨기지 않기

- 현재 앱의 상태는 ‘모집 중 → 답변자 수락 → 답변 도착 → 여행자 채택’으로
  이해할 수 있어야 합니다. 등록 성공은 답변 보장과 다릅니다.
- 승인 가이드 수는 ‘지금 응답할 수 있는 인원’과 다릅니다. 실제 가용성을
  측정하지 않는 현재 단계에서는 승인 계정 수를 온라인 수처럼 표시하지
  않습니다.
- 처음에는 운영자가 지역별 열린 질문 수, 가장 오래 대기한 질문, 수락 후
  아직 답변이 없는 질문, 가이드별 진행 중 질문을 확인하는 방식이 현실적입니다.
  이 운영은 담당자와 주기가 정해져야 하며 현재 사람을 배정하지 않았습니다.
- 가이드가 감당할 수 있는 동시 질문 수와 배정 방식은 파일럿 결과로 정합니다.
  아직 검증되지 않은 자동 배정·순위 경쟁을 추가하지 않습니다.

### 3. 취소·환불은 상태별로 결정

현재 구현된 동작:

- 질문 등록 시 가상 포인트를 보관합니다.
- 답변자가 아직 수락하지 않은 질문은 질문자가 취소할 수 있습니다.
  가상 포인트는 한 번만 돌아옵니다.
- 답변자 수락 후에는 현재 MVP에서 임의 취소·환불을 허용하지 않습니다.
- 질문자가 답변을 채택하면 보관 포인트가 답변자에게 한 번만 지급됩니다.
- API는 만료된 질문의 수락을 거절하는 검사만 갖고 있습니다. 질문에
  자동 만료 시각을 부여하거나, 정해진 시간이 지나면 자동 환불하는
  운영 정책/스케줄러는 아직 켜지 않았습니다.

결정할 정책:

- 답변자 미매칭 질문의 최대 대기시간과 자동 종료/환불 여부
- 수락 후 답변이 오지 않을 때의 기한·재배정·가상 포인트 반환 절차
- 답변은 왔지만 채택되지 않는 경우의 이의 제기·검토 담당자
- 가이드 부재 시간의 질문 접수 방식

이 기한들은 실제 공급과 운영 역량을 확인한 뒤 정해야 합니다. 이번 개발에서
임의의 응답 보장이나 새로운 금전적 약속을 만들지 않았습니다.

### 4. 가이드 모집과 동기

- 모집 전 먼저 활동 도시·가능 시간·사용 언어·답할 수 있는 주제를
  확인하는 짧은 신청 문항을 준비합니다. 실제 모집 메시지는 아직 발송하지
  않았습니다.
- 첫 가이드에게는 질문을 무작정 많이 배정하기보다, 근거를 제시한 좋은
  답변 예시와 채택 과정이 무엇인지 보여주는 온보딩이 필요합니다.
- 초기 신뢰 신호는 실제 채택 기록, 등록한 활동 지역, 공개된 근거입니다.
  없는 후기나 ‘검증된 전문가’ 배지를 만들지 않습니다.
- 가상 포인트와 실제 지급 가능한 돈을 명확히 나눕니다. 현금 보상을
  추가하려면 지급 주체·수수료·정산 시점·취소/분쟁·세금/신원 확인·결제
  제공자에 대한 별도 결정과 검토가 필요합니다. 현재는 어떤 지급 계정도
  만들거나 연결하지 않았습니다.

## 파일럿에서 볼 지표

단순 가입자 수보다 아래의 실제 흐름을 확인합니다. 목표 숫자를 지금 임의로
보장하지 않고, 작은 실제 테스트에서 기준을 잡습니다.

- 질문 등록 완료율과 위치/네트워크 문제로 포기한 이유
- 최초 답변자 수락까지의 대기시간과 미매칭 비율
- 수락한 질문 중 근거를 포함한 답변이 도착한 비율
- 답변 중 여행자가 채택한 비율과 취소 사유
- 가이드별 진행 중 질문 수, 재참여, 채택 기록
- 중복 제출/중복 보상/환불 오류와 지원이 필요했던 건수

## 다음에 확인할 결정

1. 첫 테스트 도시·생활권과 질문 종류
2. 실제 참여 가능한 가이드와 운영 담당자/시간대
3. 미매칭 및 수락 후 미답변 처리 기한
4. 계정 복구·신고·개인정보 보존과 실제 서버 운영 계획
5. 초기 가상 포인트의 무료 배분·보충 기준. 현금 보상은 이번 출시 모델에 포함하지 않음

## 참고한 운영 패턴

- Stack Overflow는 답변의 ‘채택’을 질문자가 선택한 결과로 설명합니다.
  여기서는 그 패턴을 참고하되 채택 수를 전문가 자격이나 정확성 점수로
  간주하지 않는 것이 제안입니다. [공식 도움말](https://stackoverflow.com/help/accepted-answer)
- Airbnb의 체험 운영 안내는 호스트가 실제 일정을 추가·수정·삭제하도록
  합니다. 이 앱에서도 가입/승인 여부와 실제 응답 가능 시간을 구분해야
  한다는 설계 참고이며, Airbnb의 운영 기준을 그대로 적용한다는 뜻은
  아닙니다. [공식 일정 안내](https://www.airbnb.com/help/article/2645)
