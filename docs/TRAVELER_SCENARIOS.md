# 여행자·가이드 확인 시나리오

테스트 데이터만 사용합니다. 아래는 서비스가 실제 여행 정보를 보장한다는
뜻이 아니라, 앱의 이용 흐름과 실패 복구를 확인하기 위한 시나리오입니다.

## 1. 여행 전, 여행지 밖에서 유럽·미국 질문하기

- 위치 권한을 거절하거나 현재 위치가 선택 도시에서 먼 상태로 질문 작성
- 도시를 직접 선택하고, 지도 로딩 없이 텍스트를 입력
- 도시 중심 기준의 선택임을 확인하고 필요하면 본문에 실제 장소를 추가
- 질문 예시를 고른 뒤 방문/도착 시각과 본인 상황을 채워 질문 등록
- 기대: GPS가 질문을 막지 않고, 예시를 고를 때 기존 글을 몰래 덮어쓰지 않음

## 2. 현지 이동 중 연결이 끊김

- 질문 내용을 작성하다가 앱을 닫았다가 같은 계정으로 다시 열기
- 기대: 아직 전송하지 않은 텍스트 초안을 복원
- 등록 응답을 일부러 지연/누락하고 같은 질문을 재시도
- 기대: 같은 작업 ID를 사용해 중복 질문이나 포인트 중복 보관이 발생하지 않음
- 사진을 포함한 제출이 중단된 뒤 다시 여는 경우
- 기대: 저장되지 않은 사진을 빼고 임의로 새 질문을 보내지 않음. 기존 등록
  여부를 먼저 확인하도록 안내하고 사진 복원 범위를 명확히 밝힘
- 기억한 로그인 확인 중 연결이 끊긴 경우
- 기대: 네트워크 복구 후 다시 확인할 수 있게 하며, 만료가 확정되지 않은
  세션을 단순한 통신 장애만으로 잊어버리지 않음

이 앱은 완전한 오프라인 서비스나 자동 전송 큐가 아닙니다. 서버와 통신할 수
있어야 계정 확인·등록·수락·채택을 확정할 수 있습니다.

## 3. 근거가 있는 현지 답변 받기

- 말라가 질문에 해당 지역 승인 답변자가 참여
- 답변에 공개 HTTP(S) 근거 URL과 확인 방법을 추가
- 여행자는 답변과 작성 기록, 담당 가이드의 실제 채택 기록을 보고 채택
- 기대: 다른 사람은 질문자 대신 보상을 지급할 수 없고, 반복 클릭/재시도로
  채택 수나 보상이 늘어나지 않음
- 근거의 존재는 최신성이나 정확성을 자동 인증하지 않음. 방문 시각에 따라
  달라지는 정보는 질문과 답변에서 언제 확인했는지 설명해야 함

## 4. 로컬 가이드의 동기와 신뢰

- 본인이 수락할 수 있는 지역의 열린 질문을 확인
- 채택된 답변 수, 받은 가상 포인트, 아직 채택 대기 중인 가상 포인트 확인
- 활동 기록 로딩이 느리거나 실패해도 질문 목록을 확인하고 별도로 재시도
- 빈 목록에서도 참여 방법과 본인의 활동 기록을 확인
- 기대: 별점이나 자격을 꾸며내지 않고, 실제 기록만 표시. 가상 포인트는
  실제 현금 지급이나 출금 약속으로 표현하지 않음

## 5. 사람을 바꿔가며 시험할 때

- 계정 A로 사진을 읽는 중 계정 B로 전환
- 오래 걸린 A의 로그아웃 응답이 B의 로그인 후 도착
- 기대: A의 글/사진이 B의 질문으로 등록되거나 B의 포인트가 차감되지 않음.
  오래된 응답이 새로운 계정의 로그인이나 화면 데이터를 덮어쓰지 않음

## 검증 방식과 범위

최종 실행 결과는 [VERIFICATION](VERIFICATION.md)에 기록합니다. 실제 PostgreSQL과
HTTP 경로, Flutter의 지연·실패 주입 테스트, 모바일 폭의 위젯 테스트를 구분합니다.
호스팅된 화면 캡처는 실제 Flutter 렌더 확인용이며 사람의 모든 클릭 동작이나
실제 이동통신망 성능 측정을 대신하지 않습니다.
